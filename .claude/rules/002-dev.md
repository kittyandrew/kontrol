# Development

## Gates

Run all of these before presenting work as done. `nix flake check` is also the only CI job.

```bash
nix develop -c bash -c 'cd firmware && cargo fmt --check && cargo clippy --release -- -D warnings \
  && cargo clippy --release --target x86_64-unknown-linux-gnu -- -D warnings'
nix develop -c bash -c 'cd tests/sim && cargo fmt --check && cargo clippy --release --tests -- -D warnings'
nix develop -c alejandra -c .
nix develop -c bash -c 'ruff format --check . && ruff check .'
nix flake check -L
```

Flakes see only files in git's index: `git add` a new file before any `nix` command, or it does not exist.
Iterate on the simulation without Nix: `cargo test --release` in `tests/sim/`. To see one scenario's log with
virtual times, run its binary with the scenario's name: `SIM_LOG=1 <scenarios binary> <name>`.

## Test layers

Each layer is one flake check and tests only what it alone can reach. Put a new test in the cheapest layer
where the bug it guards against can make it fail.

| Check | Runs | Proves |
|---|---|---|
| `firmware` | the Pico build | rustfmt and clippy clean |
| `config` | `tests/sim/src/parse.rs` | every reject path of `Config::parse` |
| `sim` | `tests/sim/`: the real `app::run` on virtual time, against a fake ntfy over in-memory Ethernet | every timing and failure rule, at the shipped constants, in milliseconds |
| `ntfy-contract` | `tests/sim/contract.py` against the real ntfy binary | the fake answers like real ntfy: status codes, framing, `since=`, keepalives |
| `emu` | `tests/emu/`: the release ELF in rp2040js, flashed by the real kontrol-flash | the config verdict on the USB log, the watchdog reset after STALL, the 0x02 reboot into BOOTSEL |
| `wake` | `tests/vm/wake.nix`, a NixOS VM | real TLS through Caddy with a chain over 4 KiB, DHCP, DNS, one wake and its replay |

- **Only tests that can fail stay.** When adding a test, plant the bug it guards against and show it fails,
  then passes without the bug. A test no planted bug can fail is deleted.
- **The emulator stops at the radio**, which rp2040js does not model: nothing past `cyw43::new` runs there.
- **The simulation copies the board.** `tests/sim/src/main.rs` reimplements `pico.rs`'s watchdog task;
  change both together.
- **The module** has no automated test. Evaluate it through a consuming host's build, and read the generated
  `kontrol-listen` and `kontrol-handle` scripts.
- **The hardware check** (`004-hardware-check.md`) covers the radio and the real board. Say which layers ran.

## Style

- Rust: `rustfmt.toml` (131 columns); Python: ruff (`ruff.toml`, the same width); Nix: alejandra. Prose
  comments wrap at about 110 columns.
- Comments follow the global comment rules: explain what the code cannot, inline on the line they explain,
  no tombstones or history. Tag only a gotcha `@NOTE:`, a hazard `@WARNING:` or an action `@TODO:`, dated.
- `docs/design.md` and the README change in the same commit as the behaviour they describe.

## Secrets

The settings file (Wi-Fi password, the Pico's token) lives outside every repository with mode 600. Never
print a value from it, or a token: pipe them, and report only key names and value lengths. ntfy tokens are
`tk_` plus 29 characters; the tokens in `tests/` are fixtures, not secrets.

## Dependencies

- Rust crates: `cargo update` in `firmware/` and in `tests/sim/`, which pins the same crates for `app.rs`;
  the Nix builds read each `Cargo.lock` directly.
- The CYW43439 blobs in `nix/firmware.nix` are pinned to embassy's tag for the `cyw43` crate version in use.
  Bump the URL rev and hashes together with the crate.
- Toolchain and nixpkgs: `nix flake update`. A new ntfy can change the JSON event shape `app::Event` reads.
